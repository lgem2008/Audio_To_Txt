# Windows 打包体积缩减记录

## 结果

精简方案已接入正式源码和两份打包配置，精简 FFmpeg 本体为 **8.07 MiB**，支持常见音频和视频音轨转写。

| 发布包 | v1.0.0 | v1.0.1 | 缩减比例 |
| --- | --- | --- | --- |
| 含模型版 | 136.51 MiB | 106.46 MiB | 约 22.0% |
| 轻量版 | 64.13 MiB | 34.26 MiB | 约 46.6% |

## 核心思路

视频转写只需读取容器中的音轨，再完成音频解码和重采样。围绕这条路径精简组件，可以节省视频编码、画面处理等组件的空间。

- **替换解码组件**。用定制 FFmpeg 提取音轨，输出 16 kHz、单声道、float32 音频，通过管道交给原有转写逻辑。
- **精简打包依赖**。打包时排除 PyAV，按需收集 sherpa-onnx、ONNX Runtime 和 Windows x64 拖拽组件，减少 `collect_all()` 带入的额外文件。
- **保持识别流程**。提取出的音频继续经过 Silero VAD 分段和 Paraformer INT8 识别。

初次体积分析时，PyAV 与 FFmpeg 相关文件压缩后约占 **30.6 MiB**，因此优先优化这一部分。

## 制作过程

1. 记录原 FFmpeg 的 SHA256，并把源码、工具和实验代码放进 `build/ffmpeg-slim/`。
2. 准备 FFmpeg 8.1.1 源码、便携 w64devkit 2.11.0 和 NASM 2.16.03，编译环境仅对构建子进程生效。
3. 从 `--disable-everything` 开始，启用容器解析、原生音频解码、PCM 输出和重采样，使用 `--enable-small`、`-Os` 和静态链接生成独立 EXE。
4. 在实验代码中接入 FFmpeg 子进程，处理解码错误，并在取消操作时结束、回收子进程。
5. 生成独立测试版，对比新旧解码数据和转写结果，复核原 FFmpeg 的 SHA256。
6. 接入正式代码，按需收集打包依赖，生成含模型版与轻量版 ZIP。

精简 FFmpeg、许可与构建信息保存在 `assets/ffmpeg/`。重新构建使用 `packaging/build_ffmpeg.py`，固定版本、下载校验值和参数保存在 `packaging/ffmpeg-build.json`。

## 遇到的问题与解决方法

| 问题 | 解决方法 |
| --- | --- |
| 编译工具整包下载长时间停滞 | 改为分段下载、并发获取，校验每段长度后合并。 |
| Windows 临时路径的反斜杠被构建脚本错误解析 | 为构建子进程设置独立临时目录，统一使用正斜杠路径。 |
| `--enable-muxer=f32le` 未匹配到组件 | 构建参数使用 `--enable-muxer=pcm_f32le`，运行时输出格式使用 `-f f32le`。 |
| Make 日志出现 `@printf` 执行错误 | 使用 `make V=1`，绕过简略日志包装。 |
| 首段真实录音没有检测到人声，转写对比缺乏有效样本 | 重新截取有人声的片段，并要求测试必须识别出文字。 |

## 验证与产物

- **格式验证**。23 个有效音视频样本通过验证，覆盖 MP4、MOV、MKV、WebM、AVI、TS 等容器及中文、空格文件名。
- **功能验证**。已检查界面初始化、命令行视频转写、无音轨文件、损坏文件及取消操作。实际语音样本识别出 4 个片段，结果与原方案一致。
- **原程序核验**。原 FFmpeg 的 SHA256 与制作前一致。
- **兼容范围**。其他少见格式、特殊音轨仍需结合实际文件补充验证。

本地实验与构建过程文件位于 `build/`，正式成品为 `dist/AudioToTxt_win64.zip` 和 `dist/AudioToTxt_win64_Lite.zip`。这两类目录均由 `.gitignore` 排除，源码仓库保留构建脚本、配置和精简 FFmpeg 运行组件。
